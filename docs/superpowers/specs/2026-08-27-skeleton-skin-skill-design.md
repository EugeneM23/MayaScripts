# Skeleton + skin for humanoid characters — the `manny-skeleton` skill

Date: 2026-08-27. Status: approved by the user in outline (auto placement +
user adjustment; geodesic voxel bind); the rest of the decisions were
delegated («сделай все до конца... вернусь и выдам правки»).

## What this is

Two deliverables that work together:

1. **`maya_skelfit.py`** — a root-level standalone tool (pure `maya.cmds` +
   OpenMaya, no Qt, matching the flat-file convention) that builds a UE5
   Manny-schema skeleton fitted to a humanoid mesh and binds the mesh to it
   with geodesic voxel skinning.
2. **`.claude/skills/manny-skeleton/SKILL.md`** — a user-invocable skill
   encoding the interactive workflow: the user activates it when they need a
   skeleton + skin; Claude drives the tool over the command-port bridge,
   shows screenshots at checkpoints, the user adjusts joints by hand, Claude
   mirrors, finalizes and binds.

The user is an animator; the target pipeline is the studio's existing one:
the picker (`maya_overrig`), the UE bridge (`maya_uebridge`) and UE retarget
all assume the stock UE5 Manny schema, so **the skeleton must reproduce that
schema exactly** — names, hierarchy, channel conventions.

## The workflow (what the skill encodes)

1. **Probe** the scene: target mesh, existing joints, units, ground.
2. **Build + auto-fit**: create all 93 joints from the template, fitted to
   the mesh (see Fit below). Refuse if the scene already has joints
   (same policy as Add Character: nothing happening is the safe direction).
3. **Screenshot review**: front/side viewport captures with joint X-ray;
   the user moves any joints that landed badly (or tells Claude what to move).
4. **Finalize**: mirror the edited side onto the other (positions), snap
   center joints back to the midline, re-solve every joint's orientation
   (see Orientation below), verify symmetry.
5. **Bind**: geodesic voxel skinCluster to the measured weighted-influence
   set (74 joints), maxInfluences 8.
6. **Pose test**: apply canned test poses (elbows, knees, shoulders, head),
   screenshot each, restore exactly. The user reviews deformation; problem
   zones get weight polish iterations.
7. Done when the user accepts the deformation. FBX export to UE is out of
   scope for v1 (noted as future work).

Steps 3 and 6 are checkpoints — the loop, not a straight line.

## The template (measured, not assumed)

`assets/manny_skeleton_template.json`, generated by the committed
`assets/make_skeleton_template.py` (mayapy standalone, IMPORTS the shipped
`assets/Manny_Skeleton.ma` — import never executes script nodes). Regenerate
and re-commit if the character scene ever changes.

Measured facts the design rests on (2026-08-27):

- **93 joints, single root `root` at world origin, DAG parent = world.**
- **`jointOrient` is non-zero only on `root`; `rotateAxis` is zero
  everywhere; bind orientation lives in the ROTATE channels** (82 joints
  non-zero) — confirming the CLAUDE.md fact. `rotateOrder` is xyz on all 93,
  `segmentScaleCompensate` off on all 93.
- Two skinned meshes in the file: `Skin_3p` (48 705 verts, the third-person
  body) and `Hands_1P` (21 570, first-person hands). Both bbox y −0.02..180.52.
- **`Skin_3p` weights land on 74 of the 89 declared influences.
  `thigh_l/r`, `upperarm_l/r` and `spine_05` carry ZERO weight** — those
  segments' skin rides entirely on the twist bones (which are DAG children
  of the zero-weight bones, so swing follows automatically and roll is
  distributed — exactly what `twist.py` drives). `root`, `ik_*`,
  `center_of_mass`, `interaction`, `camera_*`, `weapon_*` are never weighted.
- **Measured max influences per vertex: 8** (the skinCluster's
  `maxInfluences` attribute claims 5 — the attribute lies, per-vertex data
  does not).

The JSON stores per joint: name, joint parent, all orientation channels
verbatim, preferredAngle, radius, side/type, world position and world
matrix; per mesh: vertex count, bbox, declared and weighted influence
lists, measured max influences.

Consequence for binding: the influence list handed to the voxel bind is the
template's **weighted** list (74), not all 93 — `ik_foot_l` stands exactly
on the foot and would steal its weights, and binding `upperarm` instead of
its twists would break the convention every UE clip and the twist rig
assume.

## Fit (v1 scope, deliberately modest)

Pure function from mesh points + template → name→world-position map:

- **Uniform scale** by height: mesh bbox height / template mesh height
  (180.52). Feet stay on the ground plane (mesh min-y is the ground; a mesh
  floating off zero is warned about and fitted where it stands).
- **Arm re-aim**: the wrist is found in the mesh (centroid of the extreme-|x|
  vertex cluster, per side); the whole arm chain (upperarm→hand + everything
  riding it) is rigidly swung about the shoulder so the template
  shoulder→wrist direction matches the measured one. This absorbs the
  A-pose/T-pose difference — the single biggest pose variable between
  humanoid meshes.
- Everything else is the scaled template. Legs, fingers, spine land
  proportionally; the user's adjustment pass is the corrective, per their
  chosen workflow («авто + моя правка»).
- **Symmetry by construction**: landmarks are measured per side then
  averaged/mirrored, so the auto-fit is exactly symmetric; center joints
  (template x≈0) stay on x=0.

The test scene is Manny's own `Skin_3p` mesh (same vertex count, same
bbox), so the identity gate is exact: fitting the template onto its own
mesh must reproduce the template joint positions to numerical noise.

## Orientation (the load-bearing math)

Moving joints without re-aiming their frames breaks every convention the
toolchain relies on (twist axes, controller alignment, UE retarget). Per
joint:

- Bone direction = to its primary child (first joint child in template
  order); the **swing** S is the minimal rotation taking the template bone
  direction to the fitted one, in world space. Leaves inherit their
  parent's S. Zero-length bones (stacked joints) inherit likewise.
- New world rotation: `R_new = R_template · M(S)` (row-vector convention —
  frame axes are rows, right-multiplying rotates them in world).
- Channels: local matrix `L = W_child_new · W_parent_new⁻¹`; translate from
  L's translation, rotate from L's rotation as xyz euler. `jointOrient`
  stays exactly what the template holds (zero everywhere but root),
  `rotateAxis` stays zero — the skeleton reproduces Manny's
  bind-lives-in-rotate convention, so `dagPose`-style checks and the
  existing tools see the convention they expect.
- `root` never moves and keeps its channels verbatim.

Idempotence gate: fitting with zero position change must leave every
channel numerically at its template value.

## Binding

`cmds.skinCluster` with `bindMethod=3` (geodesic voxel),
`geodesicVoxelParams=(256, True)`, `maximumInfluences=8`,
`obeyMaxInfluences=True`, `toSelectedBones=True` with the 74-joint weighted
list, weights normalized. Target mesh = the selection, else the lone
non-intermediate mesh in the scene; ambiguity is refused, a mesh that
already has a skinCluster is refused (Bake/detach is the user's call, not
the tool's).

Post-bind smoke: rotate an elbow with autoKey off, assert vertices near it
move and the opposite arm does not, restore the exact prior values
(the `pushed` pattern from the verify scripts; trap 14).

## Tool surface (module functions, all callable over the bridge)

- `load_template()` — parse + validate JSON.
- `target_meshes()` — selection else lone mesh; refusals as above.
- `build(mesh=None)` — probe, fit, create joints, orient; returns status
  string ("93 joints on Skin_3p, scale 1.000" / refusal reason).
- `finalize(side=None)` — mirror user-edited positions onto the other side,
  midline snap, re-solve orientation. Returns what it mirrored. The edited
  side is detected against a **reference snapshot of the fitted positions
  stored on `root` as a string attribute at build time** (scene-persistent,
  like the manifests): the side whose joints diverged more from the
  snapshot is the edited one; `side="l"/"r"` overrides. Center joints keep
  their y/z edits and get x snapped to 0.
- `bind(mesh=None)` — the voxel bind. Refuses if no skeleton or already
  bound.
- `pose_test(name)` / `restore_pose()` — canned poses, exact restore.
- `screenshot(path, view="front")` — playblast one frame with joint X-ray
  forced on and restored.

No window in v1 — the skill drives functions over the bridge; a shelf
button can come later if the animator wants one (YAGNI now). Not part of
the installer payload for the same reason.

## Testing

- **Unit tests** (`tests/test_skelfit.py`, mayapy unittest, no Maya session
  needed for the pure parts; fake `cmds` injection where the thin wrappers
  need it): template parsing/validation, fit math (scale, arm swing,
  symmetry, identity on template landmarks), orientation solver (swing
  composition, euler decomposition round-trip, idempotence), mirror pairing
  table, refusal policies.
- **Live proof** `docs/superpowers/plans/verify_skelfit.py` through the
  bridge in the real test scene: build on `Skin_3p`, gates on joint count
  and exact name/hierarchy match, world positions vs template (identity
  case), L/R symmetry, channel conventions (jointOrient zero off-root,
  rotateOrder xyz), refusal on second build, bind gates (skin exists,
  influence list == weighted list, weights normalized, measured max ≤ 8),
  deformation smoke with exact restore, screenshots for the user.

## Out of scope (v1)

- FBX export of the skinned character to UE (future; `animexport` covers
  animation already, a skeletal-mesh export is its own design).
- Copy-weights-from-Manny as an alternative first pass (user picked voxel;
  add later if a character close to the mannequin wants it).
- Non-humanoid or non-bipedal characters; leg re-aim; per-finger fitting.
- Weight-painting UI — polish happens through Maya's own tools plus
  targeted `skinPercent` calls in the loop.
