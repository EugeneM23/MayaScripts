# CAT / CATMotion (3ds Max): разбор для Walk Builder

2026-10-23. Анимейтор: «Как в 3д максе был технически сделан плагин KAT, который позволял строить
и настраивать анимации бега. Давай проанализируем и соберем всю возможную информацию по кату,
сделаем документацию, чтобы потом внедрить в наш walk builder».

Исследование, кода нет. «KAT» - это **CAT, Character Animation Toolkit**, а генератор
циклов в нём называется **CATMotion**. Источники - справка Autodesk по CAT за 2010–2023 годы,
ссылки в конце. Описания в разных версиях совпадают.

Как помечены утверждения:
- **[док]** - написано в справке Autodesk;
- **[реконструкция]** - вывод из описанного поведения, в справке формул нет;
- **[память]** - помню по работе с CAT, но в справке не нашёл. Проверить в Max перед реализацией.

---

## 1. Что такое CAT

- **[док]** CAT - плагин анимации персонажей для 3ds Max: риг, нелинейная анимация, слои,
  импорт мокапа, мышцы.
- **[док]** История:
  - 2003: выпуск Character Animation Technologies (Новая Зеландия);
  - 2006: покупка Avid/Softimage, CAT 2.5 принёс три новых режима ходьбы в CATMotion;
  - конец 2008: Autodesk купил Softimage;
  - с 2009 CAT входит в базовый 3ds Max.
- **[док]** Сама Autodesk пишет, что CATMotion «предназначен в первую очередь для генерации
  базовых циклов». Сложные шаги и переходы делаются смешиванием слоёв, а не правкой каждого
  компонента.

Главное отличие от нашего Walk Builder. CATMotion **синтезирует** цикл с нуля из кривых по фазе.
Walk Builder **анализирует** готовый цикл (мокап, клип) и меняет отклонения от него. Отсюда всё,
что ниже: у CAT нет "исходника", поэтому каждый аспект движения - отдельная кривая. У нас
исходник есть, поэтому ручка - это масштаб уже снятого движения.

## 2. Архитектура CATMotion

### 2.1 Иерархия

- **[док]** CATMotion Editor (раньше CATWindow) - немодальное окно. Слева дерево, справа
  панель выбранного узла.
- **[док]** Дерево повторяет риг:
  - **Globals** - главные настройки слоя;
  - **LimbPhases** - фазы конечностей и следы;
  - **HubGroups** - группа на каждый «хаб» (таз, грудная клетка, голова). В группу входят хаб,
    его конечности и хвосты (`PelvisGroup`, `RibcageGroup`).
- **[док]** Риг состоит из пяти элементов: Leg, Arm, Spine, Tail, Extra Bone.
- **[док]** Следы (footprints) бывают только у конечностей, помеченных как нога. Поэтому
  четвероногий - просто хаб с четырьмя ногами.

### 2.2 Цикл - 100 «кадров» фазы

- **[док]** Каждый цикл занимает 100 кадров. Время на кривых - это проценты цикла: 50 - его
  середина.
- **[док]** Реальная длина получается растяжением или сжатием. Её задают Globals
  (`Max Step Time`, `Max Stride Length`) и скорость Path Node.
- **[док]** Фон графика показывает фазы ноги: светло-зелёный - нога на земле, тёмно-зелёный -
  в воздухе.

### 2.3 Контроллер - кривая из четырёх точек

- **[док]** Почти у каждого компонента движения свой контроллер. Это сплайн из 4 узлов (knots)
  по фазе цикла. У узла есть:
  - **Time** - положение в цикле;
  - **Value** - значение;
  - **Tangent** - угол касательной;
  - **Lengths** - длины входящей и исходящей касательных.
- **[док]** Инструменты кривой:
  - **Make Unique** - своя дорожка у каждой конечности, цветом конечности;
  - **Lock** - общие настройки у всех дорожек (работает только при Make Unique);
  - **Copy/Paste**;
  - **Scale** - умножает все ненулевые точки и касательные;
  - **Offset** - сдвиг всех точек по времени;
  - **Reset**;
  - **Curve Editor** - те же ключи в Track View.
- **[док]** У `OffsetRot` и `OffsetPos` графика нет. Это постоянные сдвиги поворота и
  позиции, и анимировать их удобно: добавляют действие поверх цикла, вторичное движение
  остаётся.
- **[док]** Любой параметр анимируется, на любой можно повесить стандартный контроллер Max
  (Float List и т.п.). Но рекомендуется анимировать **веса слоёв**, а не параметры.
- **[док]** Итог контроллера складывается из Max Step Time, Max Stride Length, скорости Path
  Node и значений всех контроллеров группы. Формулы не опубликованы.

### 2.4 Слои (пресеты) и веса

- **[док]** Пресет - настройки всех контроллеров для одного цикла (ходьба, бег, подкрадывание).
  Хранится в текстовом файле `.cmp`.
- **[док]** Внутри одного CATMotion-слоя лежит стек таких пресетов:
  - стек считается сверху вниз, нижний важнее;
  - нижний пресет на 100 % заменяет верхние полностью;
  - нижний на 33.3 % даёт треть своего движения и две трети движения выше.
- **[док]** Веса анимируются, так получаются переходы «шаг → бег».
- **[док]** **Все пресеты внутри одного слоя используют один набор следов**, поэтому переход
  не скользит. Если смешивать разные слои Layer Manager, ноги скользят и появляются лишние
  следы.
- **[док]** Править кривую можно только когда вес слоя выше 50 %. Кривая на экране - взвешенная
  сумма слоёв, поэтому при весе меньше 100 % точки едут медленнее мыши.
- **[док]** Пресет грузится на любой риг, но 4-ногий пресет на двуногом выглядит плохо.
- **[память]** Есть ещё adjustment-слои Layer Manager поверх CATMotion - ручная правка поверх
  процедурного цикла.

### 2.5 Globals - главные параметры

| Параметр | Что делает [док] |
|---|---|
| `CATMotion Range Start/End` | Диапазон расчёта движения и следов. Сдвиг Start у одинаковых персонажей разводит их по фазе, чтобы толпа не шла в ногу. |
| `Max Step Time` (кадры) | Максимальная длительность шага. |
| `Max Stride Length` (CATUnits) | Максимальная длина шага. |
| `Velocity` | Показывает скорость. Без Path Node - из двух параметров выше, с Path Node - фактическую. |
| `Direction` (градусы) | Направление движения в режимах Walk On Spot / Walk On Line. Не поворачивает персонажа: 90 - боком (страйф), 180 - назад. |
| `Gradient` | Уклон воображаемой поверхности (подъём или спуск). Не поворачивает персонажа. |
| `Walk Mode` | **Walk On Spot** - на месте. **Walk On Line** - по Direction и Gradient. **Walk on Path Node** - за объектом сцены. На первых двух режимах шаги всегда равны Max Stride Length и Max Step Time. |
| `Path Node` | Любой объект: Point, Dummy, объект на Path constraint, скрипт, делегат Crowd. Иногда его надо довернуть. |
| `Preserve Character Shape` 0..1 | Для горизонтального позвоночника (четвероногие). 0 - позвоночник повторяет траекторию Path Node (в тугих поворотах странно), 1 - держит форму. |
| `Retargeting` 0..1 | Смесь IK (0) и полного ретаргетинга (1) для ног, см. 2.8. |

**[док]** С Path Node риг сам меняет длину шага под скорость. Max Step Time и Max Stride Length
он при этом не превышает.

**[реконструкция]** Правдоподобный закон:
- Шаг идёт с периодом `Max Step Time`, пока `v · MaxStepTime ≤ MaxStrideLength`: длина шага
  растёт со скоростью.
- Выше этой скорости длина упирается в максимум, и укорачивается время шага:
  `t = MaxStrideLength / v`.
- То есть медленно - короткие шаги в обычном ритме, быстро - максимальные шаги всё чаще. Так
  ведёт себя человек.
- Одно не выяснено: шаг это или двойной шаг (stride). В справке это не уточнено.

### 2.6 LimbPhases - фазы и следы

- **[док]** На каждую конечность (руки тоже) - ползунок фазы, её сдвиг относительно общего
  цикла («каденс»):
  - одинаковые значения - конечности движутся вместе;
  - разница в половину шкалы - строго в противофазе.
- **[док]** Так задаются аллюры: двуногий в противофазе; у четвероногого четыре ползунка дают
  шаг, рысь, иноходь, галоп.
- **[док]** Footprints - вспомогательные объекты, по одному на каждую постановку стопы:
  - **Create / Delete**: Delete прячет следы, правки помнятся, но анимация следов теряется;
  - **Reset** - всё или выделенные на исходное место;
  - **Pick Ground** - посадить следы на поверхность (пример - Plane с Ripple). С Auto Key
    каждые 4–5 кадров - ходьба по анимированной поверхности;
  - **Step Masks** - когда Path Node встал и следы легли друг на друга, персонаж
    останавливается, и снова идёт, когда Path Node тронулся. Не мгновенно: дошагивает
    последний шаг и начинает чуть заранее.
- **[док]** Следы можно анимировать (поскользнуться на повороте), привязать к space warp или
  Attachment constraint.
- **[док]** Правка следа двигает хаб: у двуногого хаб встаёт посередине между следами, у
  четвероногого сдвигается на четверть.

### 2.7 Контроллеры по частям тела

Справка не перечисляет все контроллеры хабов. Подтверждено:

**Таз (Pelvis), 8 контроллеров.**
- **[док]** Twist, Roll, Lift, Push - названы явно.
- **[док]** OffsetRot и OffsetPos (без графиков) упомянуты как общие.
- **[память]** Остальные, скорее всего, Pitch и WeightShift (боковой перенос веса).

**Грудная клетка, голова, позвоночник** (хабы и Spine).
- **[док]** Есть свои группы.
- **[док]** Пример «вторичное движение вроде Head Lift» - значит у головы есть Lift.
- **[память]** У хабов набор похож на тазовый. Позвоночник раскладывает разницу между хабами.

**Нога (Limb), только у ног.**
| Контроллер | [док] |
|---|---|
| `LiftPlantMod` | Доля времени на земле и в воздухе, единственный ползунок под графиком. Влево - стопа дольше на земле («походка на Юпитере»). Вправо, если дойти до светлой зоны, обе стопы в воздухе - **бег**. Анимируется для переходов шаг ↔ бег. |
| `KneeAngle` | Угол колена в 4 точках цикла: **MidPlant** (между Plant и Lift), **Lift** (перед отрывом), **MidLift** (середина полёта), **Plant** (постановка). Работает через ретаргетинг. |
| `LegWeight` | Насколько стопу тянет к земле. 0 - больший угол колена поднимает стопу, 1 - тянет таз вниз. Ещё и приоритет: левая часть графика - Lift, правая - Plant. Когда углы физически недостижимы, 1/0 решает, где окажется ошибка. Обычно приоритет у опорной ноги. |

**FootPlatform (IK-цель стопы).**
| Контроллер | [док] |
|---|---|
| `Lift` | Высота стопы по фазе. Масштабируется CATUnits. |
| `RollPivotPos` | Точка поворота поперёк стопы: 0 - внутренний край, 1 - внешний (человек 1.0). |
| `Roll` | Крен вдоль длины стопы. Начинается до отрыва, кончается после постановки. |
| `PitchPivotPos` | Точка поворота вдоль стопы: 0 - пятка, 1 - носок. У человека едет от носка (отрыв) к пятке (постановка). |
| `Pitch` | Наклон стопы при отрыве и шлепке. |
| `FootPush` | Циклический сдвиг стопы вперёд по Y, выбрасывает её вперёд. |
| `Swerve` | То же, что WeightShift: боковой (X) циклический сдвиг стопы. |
| `StepShape` | Скорость стопы в воздухе, то есть ease-in/out переноса. Медленно - большие ease, бег - почти линейно. |

**Голеностоп (Ankle).**
| Контроллер | [док] |
|---|---|
| `TargetAlign` | Где пивот голеностопа: 0 - подушечка (основание пальцев), 1 - сустав. Человек: подушечка на отрыве, пятка на постановке. Пальцеходящие - постоянно 0. |
| `FootBend` | Угол голеностопа. Человеку обычно не нужен (стопа сама поднимается при правильном TargetAlign), нужен пальцеходящим. |
| `DigitRollAngle`, `DigitSpreadAngle`, `DigitCurlAngle` | Перекат, развод и сгиб пальцев. Только если у стопы есть пальцы. Развод для динозавров, сгиб для когтей; вес сгиба на каждый палец отдельно. |

**Руки.**
- **[док]** `Swing` - мах вперёд-назад параллельно телу.
- **[док]** `CrossSwing` - отвод руки от тела вокруг её Y. Вместе с Twist задаёт дугу маха
  вокруг тела.
- **[док]** `Bend` - сгиб локтя. Пример для человека: узел 1 = −64, узел 2 = 24.
- **[док]** Ключица: `MotionX`, `MotionY`, `MotionZ` - по циклу вращения на ось.
- **[док]** Ладонь (Palm): как голеностоп, плюс `HandFlop` - «болтание» кисти.

**Хвост.**
- **[док]** От 1 до 100 звеньев, жёсткость задаётся графиком Tail Stiffness. На голове хвост
  работает как дреды, хвостик, рог.
- **[память]** У CATMotion для хвоста своё качание по фазе с запаздыванием вдоль цепи.

### 2.8 Ретаргетинг - «вес» из прямых ног

- **[док]** Обычный IK держит хаб на месте и двигает только цель. Ретаргетинг держит решение IK
  и углы костей ноги, а **хаб толкает, тянет и поворачивает**. Ноги поднимают таз, отсюда
  автоматический «вес». Колено не щёлкает при перетянутом IK, можно делать совсем прямые ноги.
- **[док]** Ошибка системы уходит в голеностопы. Если голеностопы лезут вверх, уменьшить Max
  Stride Length, поменять KneeAngle, сгладить LegWeight. Если стопа слишком прямая на отрыве,
  слишком длинная часть Lift у LegWeight.
- **[док]** **Для бега и прыжков ретаргетинг плох**: момент, где отпускается вес ног и
  начинается полёт, почти невозможно смешать. Для бега рекомендован IK (`Retargeting` = 0).
- **[док]** `Allow IK Rotations`: вкл - хаб и вращается, и сдвигается; выкл - только сдвигается
  (грудь прямая).

### 2.9 CATUnits

- **[док]** `CATUnits Ratio` на CATParent умножает длины всех костей и масштабирует движение
  CATMotion, включая высоту подъёма стопы. Так один пресет годится на персонажей разного роста.
  Больший персонаж - больший ratio.

### 2.10 Известные проблемы на практике

- Колени «щёлкают» между прямым и согнутым на циклах CATMotion. Тема на Polycount (закрыта
  403, видел только заголовок и выдержки в поиске). Советы: процедурно в окне CAT или руками
  через таз. Отдельно отмечено, что в CAT нет независимого вращения бёдер без влияния на
  иерархию.
- Скольжение при смешивании разных слоёв Layer Manager [док].
- Бег с ретаргетингом [док].

## 3. Как это, вероятно, считается [реконструкция]

1. **Время → фаза.** Из скорости Path Node и Globals берутся длина и время шага (2.5). Глобальная
   фаза `φ ∈ [0, 100)` растёт на `100 / T_cycle` за кадр.
2. **Фаза конечности** `φ_i = φ + offset_i` (LimbPhases).
3. **Земля / воздух.** LiftPlantMod делит цикл на опору и перенос. Пропорция - доля опоры,
   при доле меньше 50 % обе стопы в воздухе.
4. **Следы.** На каждую постановку - след: позиция Path Node в момент постановки плюс сдвиг
   конечности от хаба, плюс Direction и Gradient. Следы хранятся, их можно править.
5. **Стопа (FootPlatform)** в опоре стоит на своём следе. В переносе едет от следа к следу:
   - профиль скорости `StepShape`;
   - сверху `Lift` (высота), `FootPush` (вперёд), `Swerve` (вбок);
   - повороты `Pitch` и `Roll` вокруг пивотов `PitchPivotPos` и `RollPivotPos`.
6. **Хаб (таз)** стоит в середине между следами (двуногий) или в среднем по четырём. Сверху -
   его кривые: `Lift` (боб), `Push` (вперёд-назад), `WeightShift` (вбок), `Twist`, `Roll`,
   `Pitch`, `Offset*`.
7. **Ноги** решаются IK, при `Retargeting` > 0 - ретаргетингом: углы колена из `KneeAngle`, хаб
   подвигается до решения, `LegWeight` решает, кто уступает.
8. **Верх**: позвоночник и грудь своими кривыми, руки `Swing`, `CrossSwing`, `Bend` по фазе своей
   руки, ключицы `MotionXYZ`, голова и хвосты.
9. **Смешивание**: каждая кривая - взвешенная сумма слоёв, следы общие.

## 4. CATMotion и Walk Builder рядом

| Возможность CAT | В Walk Builder | Комментарий |
|---|---|---|
| Синтез цикла из кривых с нуля | Нет. Нужен исходный клип | Принципиальная разница (1). |
| Цикл как фаза 0..100 | Есть: фаза шага, `stride_phase` | |
| Max Step Time / Max Stride Length | `tempo`, `stride` | У нас без закона «скорость → шаг». |
| Walk On Spot | `in_place` | |
| Walk On Line + Direction (страйф, назад) | Нет как ручки. Направление берётся из исходника (назад, по диагонали - да) | Можно сделать ручку «Direction». |
| Gradient (склон) | Нет | Новое. |
| Walk on Path Node | Нет (в «Not built»: кривая походка) | Самое крупное, что можно взять. |
| Слои-пресеты с весами и общими следами | Нет. Один цикл, один Pose share | Переходы шаг → бег. |
| LimbPhases (сдвиг фазы ноги или руки) | Нет | Хромота, асимметрия, четвероногие. |
| Footprints: правка, Pick Ground, Step Masks | Нет. Есть фиксация опоры `foot_placement` | Неровная земля, остановка и старт. |
| LiftPlantMod | `ground_time`, сохранение полёта у бега | Есть, по сторонам. |
| KneeAngle в 4 фазах | Нет. Колено из IK, `leg_turn`, `knee_foot` | Новое: «согнутость колена на опоре и в полёте». |
| LegWeight / ретаргетинг (таз садится от ног) | Опускание таза на дотяжку, Balance | Похоже по смыслу, у нас физичнее. |
| FootPlatform Lift / FootPush / Swerve | `lift`, `swing_out` | FootPush нет. |
| StepShape (ease переноса) | Нет | Новое и простое. |
| Pitch / PitchPivotPos / TargetAlign (пятка → носок) | Перекат пятка ↔ подушечка, `foot_flex`, `foot_flat`, `foot_lag` | Пивот у нас вычисляемый λ, ручки нет. |
| Roll / RollPivotPos (крен стопы) | Нет | Новое. |
| Digit* (пальцы) | Нет | Для существ. |
| Pelvis Twist / Roll / Lift / Push / WeightShift | `pelvis_twist`, `pelvis_list`, `bob`, `surge`, `sway`, `pelvis_rot` | Есть, у нас в градусах и см. |
| Pelvis Offset* | `pelvis_height`, `pelvis_forward` | Есть. |
| Грудь / позвоночник | `chest_twist`, `chest_sway`, `spine`, `gait_lean`, пружины корпуса | У нас богаче (инерция). |
| Arms Swing / Bend | `arms`, `elbow`, инерция рук | |
| CrossSwing | Нет | Новое. |
| Collarbone MotionXYZ | Нет (ключица только через Pose) | Новое. |
| HandFlop | Частично `arm_drag` / `arm_bounce` | |
| Хвосты | Нет | Для Creep и существ. |
| Head Lift | `head`, `head_drag` | |
| Make Unique / Lock | Both / Left / Right (`SIDED`) | Есть. |
| CATUnits Ratio | Размер по длине ног при переносе | Есть, считается автоматически. |
| Start offset (разфазить толпу) | Нет | Тривиально. |
| Preserve Character Shape | Не нужно без пути | Только вместе с Path Node. |
| Кривая на любой параметр | Нет: ручки скалярные | См. 5.6. |

Чего у CAT нет, а у нас есть:
- исходный стиль из мокапа;
- позы-карточки (Pose share, по частям тела);
- Balance (центр масс над опорой, маятник);
- пружинная инерция корпуса, головы и рук;
- Foot placement без скольжения при любом исходнике;
- чистка клипа (петля, шов, Fix posture);
- несколько персонажей сразу;
- средняя поза на риге.

## 5. Что можно перенести в Walk Builder (по ценности)

### 5.1 Ходьба по пути: Path Node и закон «скорость → шаг»

Самое ценное в CAT.
- **Идея**: персонаж идёт за кривой или объектом. Шаг подстраивается под скорость в пределах
  Max Step Time и Max Stride Length. Следы ложатся по траектории, тело поворачивает.
- **У нас**: из цикла уже есть стиль, длина и темп. Нужно разложить цикл на последовательность
  шагов (`walk.steps` уже есть), ставить их вдоль пути, а в поворотах вращать опоры и таз.
- **Цена**: большая. Это уже не цикл, а непериодическая анимация. Balance, инерция и Foot
  placement сейчас периодические (FFT, `smooth_cover`).

### 5.2 Слои с весами и общими следами (переходы шаг → бег)

- **Идея**: несколько циклов в одном «слое», вес анимируется, следы одни на всех.
- **У нас**: смешать два Walk по фазе (общий шаг, вес по времени). Опоры ставить по
  смешанной траектории.
- **Цена**: средняя-большая. Нужна общая фаза двух циклов разной длины и смешивание по фазе, а
  не по кадрам.

### 5.3 Фаза каждой конечности: LimbPhases

- **Идея**: сдвиг фазы руки или ноги относительно цикла.
- **У нас**: ручки `Phase` у сторон (`phase_l`, `phase_r`) и у рук.
  - Ноги: хромота, «подволакивание». Шаги в противофазе сейчас жёстко заданы исходником.
  - Руки: независимый мах. Например, у руки с оружием мах отстаёт или стоит.
- **Цена**: малая для рук (сдвиг времени выборки, как `overlap`). Средняя для ног: меняет
  опору, Foot placement и Balance.

### 5.4 Колено по фазам: KneeAngle

- **Идея**: «согни колено на опоре», «выпрями на отрыве».
- **У нас**: четыре ручки-добавки к сгибу колена в MidPlant, Lift, MidLift, Plant. IK решает
  с другой высотой таза. Для опоры это механика ретаргетинга CAT: таз садится, стопа на месте.
  Как `smooth_cover` над опусканием таза.
- **Цена**: средняя. Прямо отвечает на щелчки колена (ловушка 239): даёт задать запас сгиба.

### 5.5 Мелкие и дешёвые

- **StepShape** - ease переноса стопы: ручка-степень на `swing_progress`.
- **FootPush** - выброс стопы вперёд в переносе.
- **Roll + RollPivotPos** - крен стопы внутрь-наружу и пивот по ширине стопы.
- **PitchPivotPos / TargetAlign** - ручка для вычисляемого у нас λ (пятка ↔ подушечка).
- **CrossSwing** - отвод руки от тела по фазе.
- **Ключица MotionXYZ** - амплитуды плеча по циклу (вверх-вниз, вперёд-назад).
- **HandFlop** - отдельная амплитуда кисти.
- **Direction** - доворот направления движения относительно тела (страйф, спиной вперёд).
  Похоже на `straightened`, только наоборот.
- **Gradient** - склон: следы на наклонной плоскости, таз и центр масс над ними.
- **Start offset** - сдвиг фазы на персонажа, чтобы толпа не шагала в ногу. Сразу пригодится
  при нескольких персонажах.
- **Пальцы ног** (curl/spread) и **хвост** - для Creep и существ.

### 5.6 Кривые вместо чисел (по желанию)

- **Идея**: у ручки есть форма по фазе. Например, `bob` - 4-точечная кривая: где пик, как
  острый. В CAT это основной интерфейс.
- **У нас**: кривая - множитель (0..1+) отклонения по фазе шага, поверх исходника. Рисуется в
  карточке как маленький график с зелёной полосой опоры. Это перенос UI CATMotion.
- **Цена**: средняя. Нужны UI и формат хранения. Модель почти не меняется: отклонение × w(φ).

### 5.7 Процедурный исходник (по желанию)

- **Идея**: «Build from scratch» - сгенерировать базовый цикл кривыми CATMotion, когда клипа
  нет. Потом это обычный Walk для всех ручек.
- **Цена**: большая. Зато Walk Builder перестанет зависеть от мокапа.

### Чего не брать

- **Ретаргетинг CAT как есть** - у нас уже есть опускание таза по дотяжке и Balance, они
  точнее. И сам CAT советует для бега IK.
- **Pick Ground с Auto Key каждые 4–5 кадров** - костыль. Если делать неровную землю, то
  лучом по мешу на каждом шаге.
